## Recover the artwork

Supply the original ten separate portraits, not the v2.4 atlas. Name them using
the IDs in `app/src/main/assets/wallpapers/catalog.js` (for example
`moonlit-city.png` and `rainy-neon.png`). Originals must be at least 1080×1920.
If the original pack is smaller, obtain its full-resolution sources; do not upscale.

With Python and Pillow installed:

```text
python scripts/import-wallpapers.py PATH_TO_ORIGINALS
npm ci
npx playwright install chromium
npm test
```

The importer keeps the portrait aspect ratio and never enlarges artwork. It tries
lossless WebP first, uses quality 96 only when necessary, requires ≥38 dB PSNR,
records source and output hashes/dimensions, and caps the compressed pack at 16 MB.
Review all ten on 16:9, 20:9 and tall phone screens for composition and center-left
negative space before release. Quality thresholds cannot prove composition.

`npm run test:ui` uses explicitly synthetic wallpaper fixtures for interaction
checks. `npm run test:wallpapers` separately checks the actual original assets
and currently fails because those files have not been recovered.

The build workflow compiles Android and runs native tests before checking the
wallpaper quality gate. It cannot upload artifacts or publish a release while
that gate fails. A compiled candidate with missing artwork is not a corrected APK.

Once the original assets and checks pass, merging the branch triggers the usual
stable-debug-key test APK release as v2.5. Verify the actual release asset and its
direct HTTP download before announcing it. Physical-device validation remains
necessary for the system photo picker, status-bar appearance, and perceived motion.
